# Rules for committing and pulling code to the main branch

1. Commit messages should be concise and descriptive, following the format: `[Component]: Brief description of changes`
2. Pull requests must be reviewed by at least one other developer before merging into the main branch
3. Code should be tested locally before committing to ensure functionality and adherence to coding standards
4. Merge conflicts should be resolved promptly to maintain a clean and consistent codebase
5. Regularly update local branches with the latest changes from the main branch to avoid merge conflicts
